# V6 Source Code Archive

## Historical Overview
- **Release / Snapshot Date:** May 1975
- **Authors & Key Contributors:** Ken Thompson, Dennis Ritchie, with contributions from Douglas McIlroy, Robert Morris, and Bell Telephone Laboratories researchers.
- **Target Machine Architecture:** DEC PDP-11 (specifically the PDP-11/40, PDP-11/45, and PDP-11/70 with 18-bit addressing; kernel binary image size was approximately 29 KB).
- **Historical Milestones:**
  - **The Legendary Lions' Commentary Kernel:** Sixth Edition is the most academically influential operating system release in computer science history. In 1976, Australian professor **John Lions** (University of New South Wales) wrote *A Commentary on the UNIX Operating System*, accompanied by a complete printed source booklet of this exact V6 kernel (~9,000 lines of C and assembly). For over twenty years, computer science students and hackers circulated photocopies of Lions' book as a legendary underground samizdat manual.
  - **The Immortal Comment:** Features the single most famous code comment in computer history: `/* You are not expected to understand this. */` in `usr/sys/ken/slp.c` describing the tricky stack adjustment and context restore (`aretu`) across swapped processes.
  - **The Portable C Library:** Introduced Mike Lesk's **Portable C Library** (`usr/source/iolib`), the historic direct predecessor to standard C input/output (`stdio.h`).
  - **The Berkeley Genesis:** In late 1975, Ken Thompson spent a sabbatical year at UC Berkeley teaching V6 internals. Bill Joy and Chuck Haley received this tape, modified the kernel, added Pascal and ex/vi, and produced 1BSD from it.
  - **Source Provenance:** Sourced from `Dennis_v6` archive tarballs preserved and donated by Dennis Ritchie to TUHS.

## Key Source Code Files

| Component / Subsystem | File Link | Description |
| :--- | :--- | :--- |
| **Process Context Switcher & The Iconic Comment** | `usr/sys/ken/slp.c` | Context switcher `swtch()`, sleep/wake synchronization, and the famous comment at line 325: `/* You are not expected to understand this. */` explaining stack pointer manipulation across `aretu(u.u_ssav)` when restoring swapped processes. |
| **Kernel Initialization & Process 0** | `usr/sys/ken/main.c` | Boot routine `main()`: clears core, initializes memory maps (`mfree`), attaches root filesystem, and launches scheduler loop. |
| **System Call Dispatcher** | `usr/sys/ken/sysent.c` | System call vector table mapping PDP-11 `sys` traps directly into C functions (`sysfork`, `sysread`, `syspipe`, `sysexec`). |
| **Process Lifecycle Primitives** | `usr/sys/ken/sys1.c` | Core process manipulation: `fork()`, `exece()`, `wait()`, and `exit()`. |
| **Pipes Implementation** | `usr/sys/ken/pipe.c` | Interprocess communication pipes: manages anonymous inodes, reader/writer locks (`plock`, `prele`), and 4096-byte pipe buffers. |
| **Pathname Resolution Engine** | `usr/sys/ken/nami.c` | Function `namei()`: iteratively reads directory blocks on storage devices to map paths into inode numbers. |
| **Block Buffer Cache** | `usr/sys/dmr/bio.c` | Block I/O buffer management: `bread()`, `bwrite()`, asynchronous caching, and disk queue sorting. |
| **TTY Line Discipline** | `usr/sys/dmr/tty.c` | Teletype character driver: raw and cooked modes, character echo, erase/kill processing, and circular clist buffers. |
| **DEC Disk Drivers** | `usr/sys/dmr/rk.c`, `usr/sys/dmr/rp.c` | Moving-head disk cartridge and disk pack drivers. |
| **Portable C Library** | `usr/source/iolib/` | Mike Lesk's historic library: early implementations of `fopen`, `fread`, `fwrite`, `fputs`, and buffered character streams that directly evolved into `stdio.h`. |
| **The V6 Assembly Shell** | `usr/source/s2/sh.c` | The Sixth Edition Shell (Thompson Shell) written in C, handling argument expansion, pipelines, and background jobs. |
| **Hardware Vectors & Boot** | `usr/sys/conf/low.s`, `usr/sys/conf/m40.s` | Low-memory trap vectors and hardware MMU segment registers for PDP-11/40. |

## Recommended Exploration Path

To study Sixth Edition Unix as students did for decades with the Lions' Commentary:

1. **Start with the Core Data Structures:**
   Read `usr/sys/param.h`, `usr/sys/user.h`, and `usr/sys/proc.h`. Understanding `struct user` and `struct proc` is crucial for understanding the entire system.
2. **Follow the Boot Sequence:**
   Trace `usr/sys/conf/low.s` into `usr/sys/ken/main.c`. See how the core memory map is partitioned and how process 0 enters the scheduling loop.
3. **Analyze the Process Scheduler & The Immortal Comment:**
   Read `usr/sys/ken/slp.c` carefully. Study lines 315–336 to understand why John Lions spent several pages dissecting the tricky process stack switch.
4. **Follow Buffer Management & Disk I/O:**
   Read `usr/sys/dmr/bio.c` to understand how the block buffer cache coordinates read-ahead and write-behind with block device drivers like `usr/sys/dmr/rk.c`.
5. **Inspect the Genesis of Standard I/O:**
   Browse `usr/source/iolib/` to see how Mike Lesk designed buffered I/O functions that laid the groundwork for ANSI C `stdio.h`.
