# 2.9BSD Source Code Archive

## Historical Overview
- **Release Date:** July 1983
- **Key Developers:** Steven Schultz, Keith Bostic, Michael J. Karels, Bill Joy, Kirk McKusick.
- **Machine Architecture:** DEC PDP-11 (PDP-11/70, 11/44, 11/45, 11/24, etc.).
- **Historical Milestones:**
  - 2.9BSD marked the evolution of 2BSD from an add-on package into a **complete, standalone operating system** for the PDP-11.
  - Derived from AT&T Research UNIX Version 7 (V7) merged with 2.8BSD, it backported major innovations from the 32-bit **4.1cBSD** VAX development stream into the 16-bit PDP-11 architecture.
  - Overcame the strict 64KB PDP-11 memory limit through a split Instruction/Data (I/D) architecture, kernel overlays, and disk-swapping optimizations.
  - Introduced automatic hardware probing and configuration (`usr/src/sys/autoconfig`), eliminating manual kernel peripheral hardcoding.
  - Included a modernized filesystem with 1KB blocks and disk drivers for DEC storage controllers (hk, rk, rl, rp, xp).

## Directory Tree & Navigation Map
```
2.9BSD/
├── READ_ME          # Instructions on bootable kernel images (hkunix, rkunix, etc.)
├── genallsys.sh     # Patching script for generating bootable kernel configurations
├── bin/             # Root binary utilities
├── dev/             # Device special node creation script (MAKE)
├── etc/             # System configuration, daemon scripts, sample fstab
├── lib/             # Language support libraries (f77_strings)
└── usr/             # Primary system directory
    ├── src/         # System source tree
    │   ├── sys/     # Full PDP-11 operating system kernel source
    │   │   ├── sys/        # Machine-independent kernel routines
    │   │   ├── dev/        # PDP-11 device drivers (disks, tapes, serial lines)
    │   │   ├── autoconfig/ # Hardware auto-configuration engine
    │   │   ├── conf/       # Kernel build rules and configuration files
    │   │   ├── stand/      # Standalone bootblocks and diagnostic utilities
    │   │   └── GENERIC/    # Pre-built generic kernel configuration
    │   ├── ucb/     # Berkeley userland commands (csh, vi, delivermail, etc.)
    │   ├── lib/     # C runtime library and compiler support
    │   ├── cmd/     # Standard UNIX utilities
    │   └── games/   # BSD games suite
    ├── include/     # C header files (<sys/*.h>, standard headers)
    ├── doc/         # Technical documentation and BSD papers
    ├── ingres/      # The INGRES relational database system
    └── man/         # Manual pages across all sections
```

## Key Source Code Files
| File Path | Description & Architectural Significance |
| :--- | :--- |
| `usr/src/sys/sys/main.c` | PDP-11 kernel initialization, process 0 startup, and root filesystem mount. |
| `usr/src/sys/sys/mch.s` | Low-level PDP-11 assembly routines: MMU management, context switches, interrupt vectors. |
| `usr/src/sys/sys/trap.c` | Handles PDP-11 hardware faults, MMU page faults, and system calls. |
| `usr/src/sys/sys/slp.c` | Kernel process scheduling, context switching, `sleep()`, and `wakeup()`. |
| `usr/src/sys/sys/machdep.c` | Machine-dependent memory sizing and PDP-11 hardware register manipulation. |
| `usr/src/sys/autoconfig/autoconfig.c` | Probes UNIBUS/Q-bus vectors and device addresses dynamically at boot. |
| `usr/src/sys/sys/alloc.c` | Inode and disk block allocation algorithms. |
| `usr/src/ucb/csh/sh.c` | Source code for the 2.9BSD C Shell. |
| `usr/src/ucb/delivermail/main.c` | Eric Allman's delivermail system (antecedent of sendmail). |

## Recommended Exploration Path
1. **Understand Kernel Bootstrap (`usr/src/sys/sys/`):**
   - Begin with `usr/src/sys/sys/mch.s` to see how 16-bit PDP-11 MMU registers (PAR/PDR) are configured.
   - Trace kernel boot in `usr/src/sys/sys/main.c`.
2. **Examine Dynamic Hardware Detection (`usr/src/sys/autoconfig/`):**
   - Read `usr/src/sys/autoconfig/autoconfig.c` to observe how UNIX evolved from hardcoded hardware addresses to dynamic probing.
3. **Study Memory Management on 16-Bit Hardware:**
   - Inspect `usr/src/sys/sys/machdep.c` and `usr/src/sys/sys/slp.c` to see how kernel overlays and swapping were managed within tight RAM limits.
4. **Explore Userland Utilities (`usr/src/ucb/`):**
   - Compare `usr/src/ucb/csh/` and `usr/src/ucb/delivermail/` with their 2BSD and 4BSD counterparts.
