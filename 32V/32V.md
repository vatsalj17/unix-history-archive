## Historical Overview

| Attribute | Details |
| :--- | :--- |
| **System Name** | UNIX 32V (UNIX / 32V) |
| **Release Date** | May 1979 |
| **Origin / Creators** | Bell Laboratories (Murray Hill, NJ) — John F. Reiser and Tom London |
| **Source Donation** | Donated to TUHS (The Unix Heritage Society) by Keith Bostic |
| **Target Architecture** | DEC VAX-11/780 (32-bit CISC, VAX/VMS native hardware) |
| **Key Historical Milestones** | Direct 32-bit port of Version 7 UNIX (V7); ancestor of both 3BSD/4.xBSD and AT&T System III/System V 32-bit ports |

### Significance & Historical Context
When Digital Equipment Corporation released the 32-bit VAX-11/780 minicomputer in late 1977, Bell Laboratories researchers sought to bring their popular Version 7 UNIX (then running on 16-bit PDP-11s and Interdata 7/32) to DEC's new flagship hardware. In 1978–1979, John Reiser and Tom London undertook the port, designating it **32V**.

Crucially, although the VAX-11/780 featured a hardware page-table architecture capable of demand-paged virtual memory, the initial 32V implementation retained Version 7's classic **whole-process swapping architecture**. If a program grew or needed memory, the entire process was swapped to disk rather than paging individual 512-byte pages.

This design decision sparked the birth of the Berkeley Software Distribution (BSD) on VAX. Bill Joy and Ozalp Babaoglu at the University of California, Berkeley, obtained 32V, implemented a true page-replacement and virtual memory subsystem, and released **3BSD** in late 1979. Simultaneously, AT&T used 32V as the foundational 32-bit base for its commercial line, leading directly to UNIX System III and System V. Consequently, 32V is the pivotal fork in UNIX history from which almost all modern 32-bit and 64-bit UNIX systems descended.

## Key Source Code Files

### 1. Bootstrapping and Hardware Vector Table
- `usr/src/sys/sys/locore.s`: Low-level VAX assembly startup. Initializes system control block (SCB), sets up processor status longword (PSL), manages hardware interrupt priorities (`IPL`), handles VAX machine checks, and defines the system call entry points.
- `usr/src/sys/sys/main.c`: Kernel initialization sequence (`main()`). Configures physical memory limits, allocates buffer cache headers, mounts the root filesystem, initializes process 0 (the swapper), and forks process 1 (`/etc/init`).

### 2. VAX Hardware Architecture Support
- `usr/src/sys/sys/machdep.c`: Machine-dependent VAX support routines. Configures page tables for user processes, flushes the Translation Buffer (TB), handles hardware clocks, and dispatches signals into user address spaces.
- `usr/src/sys/sys/uba.c`: DEC Unibus Adapter (DW780) interface, allocating map registers for DMA between Unibus peripherals and VAX physical memory.
- `usr/src/sys/sys/mba.c`: DEC Massbus Adapter (RH780) interface for high-speed disks (such as the RP06/RM03) and tape drives.

### 3. Memory Management & Scheduling
- `usr/src/sys/sys/slp.c`: Process scheduling, sleep, and wakeup mechanisms. Contains `sched()`—the swapper process that moves entire processes between primary memory and swap storage.
- `usr/src/sys/sys/malloc.c`: First-fit resource map allocator managing both core memory slices and swap space maps (`coremap` and `swapmap`).
- `usr/src/sys/sys/trap.c`: Hardware trap dispatcher and system call handler for the VAX `chmk` (Change Mode to Kernel) instruction.

### 4. File System and I/O Subsystem
- `usr/src/sys/sys/bio.c`: Block I/O buffer cache manager (`bread`, `bwrite`, `brelse`, `getblk`).
- `usr/src/sys/sys/iget.c`: In-memory inode allocation, cache lookup, and disk synchronization.
- `usr/src/sys/sys/nami.c`: Pathname resolution translating directory strings into inode pointers.

## Recommended Exploration Path

1. **Start with the Core Headers**: Examine `usr/src/sys/h/param.h` and `usr/src/sys/h/user.h` to understand the process structure (`struct user` / `u-area`) and system constants.
2. **Trace System Initialization**:
   - Inspect `usr/src/sys/sys/locore.s` to see how the CPU transitions from VAX console boot into C code.
   - Follow into `usr/src/sys/sys/main.c` to observe how memory is mapped and the initial processes are constructed.
3. **Analyze the Swapping Subsystem**: Read `usr/src/sys/sys/slp.c` and `usr/src/sys/sys/machdep.c`. Compare this with BSD 3BSD/4.xBSD to see how swapping whole address spaces was replaced by paging.
4. **Inspect VAX Interconnect Drivers**: Examine `usr/src/sys/sys/uba.c` and `usr/src/sys/sys/mba.c` to understand how the operating system interfaced with DEC Unibus and Massbus peripherals.
5. **Review Userland Evolution**: Browse `usr/src/cmd/` to see the classic V7 toolchain (Bourne shell, awk, C compiler) running on a 32-bit CPU.
