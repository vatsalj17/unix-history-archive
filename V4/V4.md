# V4 Source Code Archive

## Historical Overview
- **Release / Snapshot Date:** November 1973 (Kernel source snapshot: August 31, 1973).
- **Authors & Key Contributors:** Ken Thompson, Dennis Ritchie, Bell Telephone Laboratories (Computing Science Research Center).
- **Target Machine Architecture:** DEC PDP-11 (specifically the PDP-11/40 and PDP-11/45 equipped with the KT11 Memory Management Unit).
- **Historical Milestones:**
  - **The Epochal Event: Operating Systems Rewritten in C:** Fourth Edition is the monumental milestone where Ken Thompson and Dennis Ritchie completely rewrote the Unix operating system in C. In 1973, conventional computer science dictated that operating system kernels had to be written in machine assembly language for speed and control. Unix shattered this dogma, proving that high-level systems programming produced elegant, maintainable, and profoundly portable software.
  - **The `nsys` Kernel:** The surviving V4 kernel archive is known as `nsys` ("new system"), dated August 31, 1973. It is the **earliest surviving Unix operating system codebase written in C**.
  - **Ken & Dennis Partitioning:** The kernel code is cleanly partitioned into two subdirectories reflecting its co-creators:
    - `ken/`: Architecture-independent operating system logic, memory segmentation, system calls, process scheduling, and inode operations written by **Ken Thompson**.
    - `dmr/`: Low-level I/O buffering, block memory management, and device drivers written by **Dennis M. Ritchie**.
  - **Language Nuances:** Features Dennis Ritchie's early C syntax, including compound assignments with reversed operator tokens (`=+' instead of `+=`, `=-` instead of `-=`, and `=|` instead of `|=`), untyped function returns, and octal register addresses.

## Directory Tree & Navigation Map

```
V4/
├── nsys/             [The historic earliest C kernel (nsys.tar.gz)]
│   ├── *.h           [Kernel header definitions (param, proc, inode, user, buf...)]
│   ├── tables.c      [Device switch tables (bdevsw, cdevsw)]
│   ├── ken/          [Ken Thompson: process scheduler, VM, traps, syscalls]
│   ├── dmr/          [Dennis Ritchie: block I/O cache, terminal & disk drivers]
│   └── junk/         [Assembly residue & scratch code from 1973 development]
└── man/              [Complete Fourth Edition UNIX Programmer's Manual]
    ├── docket        [Documentation tracking index]
    ├── man0/ - man8/ [Standard manual sections 0 through 8]
    └── manx/         [Supplemental manual pages]
```

### Subdirectory Breakdown
- `nsys/`: The monolithic V4 kernel written in early C and PDP-11 assembly.
  - `nsys/ken/`: High-level kernel management: process initialization (`main.c`), scheduler and sleeper (`slp.c`), system call dispatchers (`sys1.c`–`sys4.c`, `sysent.c`), inode lookup (`nami.c`, `iget.c`), block allocator (`alloc.c`), and hardware trap handlers (`trap.c`, `low.s`, `45.s`).
  - `nsys/dmr/`: I/O subsystem: block buffer cache manager (`bio.c`), memory allocator (`malloc.c`), teletype driver (`tty.c`), and hardware device drivers (`rk.c`, `tm.c`, `tc.c`, `kl.c`, `dc.c`).
  - `nsys/junk/`: Scratch assembly routines (`nps.s`, `prot.s`, `ustr.s`).
- `man/`: The complete machine-readable nroff/troff manual pages describing Fourth Edition commands, calls, and drivers.

## Key Source Code Files

| Component / Subsystem | File Link | Description |
| :--- | :--- | :--- |
| **Kernel Entry & Process 0 Init** | `nsys/ken/main.c` | Kernel bootstrap `main()`: clears core, initializes process 0 (`proc[0]`), maps the root inode, sets up `icode[]` (the embedded binary sequence executing `/etc/init`), and launches scheduler loop `sched()`. |
| **Process Scheduler & Sleep Queue** | `nsys/ken/slp.c` | Foundational scheduling primitives: `sleep()`, `wakeup()`, `setrun()`, and process state transitions between `SSLEEP`, `SRUN`, and `SZOMB`. |
| **System Call Vector & Dispatch** | `nsys/ken/sysent.c` | System call jump table `sysent[]` mapping syscall numbers to handler functions (`sysfork`, `sysread`, `syswrite`, `syspipe`, `sysexec`). |
| **Process Control System Calls** | `nsys/ken/sys1.c` | Core process manipulation system calls: `fork()`, `exec()`, `wait()`, and `exit()`. |
| **Filesystem Path Traversal** | `nsys/ken/nami.c` | The iconic `namei()` function written in C: resolves pathname strings into core inode pointers, checking search permissions along directory components. |
| **Inode Management** | `nsys/ken/iget.c` | Inode cache algorithms: `iget()` retrieves an inode from disk or buffer cache; `iput()` decrements reference count and flushes modified inodes to disk. |
| **Block Storage Allocation** | `nsys/ken/alloc.c` | Disk block allocators `alloc()` and `free()` manipulating the super-block free list. |
| **Trap & Exception Handling** | `nsys/ken/trap.c` | C handler for hardware traps, bus errors, illegal instructions, memory segmentation faults, and `sys` trap decoding. |
| **Block Buffer Cache** | `nsys/dmr/bio.c` | Dennis Ritchie's block I/O caching subsystem: `bread()`, `bwrite()`, `getblk()`, and asynchronous block buffer queues. |
| **Memory Allocator** | `nsys/dmr/malloc.c` | First-fit resource map allocator: `malloc()` and `mfree()` managing kernel swap and core memory maps. |
| **Terminal Subsystem** | `nsys/dmr/tty.c` | Terminal line discipline, character queuing (`clist`, `cblock`), and echo/erase/kill character processing. |
| **Block Device Driver** | `nsys/dmr/rk.c` | Device driver for the DEC RK05 moving-head disk cartridge controller. |
| **Device Switch Tables** | `nsys/tables.c` | Character device switch table (`cdevsw`) and block device switch table (`bdevsw`), routing major numbers to driver functions. |
| **Process State & User Area** | `nsys/user.h`, `nsys/proc.h` | Historic header definitions for `struct user` (the `u.` area) and `struct proc` (the active process table). |

## Recommended Exploration Path

Reading the Fourth Edition `nsys` kernel is one of the most rewarding exercises in computer systems education:

1. **Understand Process & User Context:**
   Open `nsys/param.h`, `nsys/user.h`, and `nsys/proc.h`. Notice how `struct user u` holds per-process state while `struct proc` resides permanently in memory.
2. **Follow the Boot Sequence:**
   Read `nsys/ken/main.c`. Trace how physical core memory is initialized using `mfree(coremap...)`, how process 0 is created, how root inode (`/`) is locked, and how the embedded binary snippet `icode[]` executes the first user-space program.
3. **Trace System Call Invocation:**
   Look at `nsys/ken/sysent.c` to see the jump table, followed by `nsys/ken/sys1.c` to see the original implementation of `fork()`, `exec()`, and `wait()`.
4. **Inspect Pathname Resolution & Inodes:**
   Read `nsys/ken/nami.c` and `nsys/ken/iget.c` to observe how Unix translated filesystem paths into file descriptors.
5. **Study the Block Buffer Cache:**
   Read `nsys/dmr/bio.c` to see how Dennis Ritchie designed buffer management (`bread`, `bwrite`, dirty writeback) that became the blueprint for modern OS page caches.
