# V1 Source Code Archive

## Historical Overview
- **Release / Snapshot Date:** November 3, 1971
- **Authors & Key Contributors:** Ken Thompson, Dennis Ritchie, with contributions from Doug McIlroy, J. F. Ossanna, and R. Morris at Bell Telephone Laboratories.
- **Target Machine Architecture:** DEC PDP-11/20 (16-bit word minicomputer, 24 KB of physical core memory without memory management unit (MMU) or paging, RF-11/RS-11 disk/drum with 512-byte blocks, and Teletype Model 33 ASR).
- **Historical Milestones:**
  - **The First Official Edition:** The first release documented in the famous "UNIX Programmer's Manual" by Thompson and Ritchie (dated November 3, 1971).
  - **Porting from PDP-7 to PDP-11:** In 1970, Bell Labs acquired a PDP-11/20 for the text processing group to prepare patent documents, justifying the purchase of the hardware. The operating system was completely rewritten from PDP-7 assembly into PDP-11 assembly.
  - **Standardization of System Calls & Inodes:** Established foundational Unix system calls that persist today: `fork`, `exec`, `wait`, `exit`, `open`, `read`, `write`, `close`, `link`, `unlink`, `stat`, `chmod`, `chown`.
  - **Birth of the Unix Shell:** Ken Thompson's standalone shell (`sh.s`) formalized command execution via fork/exec, I/O redirection (`<`, `>`), and asynchronous command execution (`&`).
  - **Source Provenance:** The kernel source survived in a printed Bell Labs document entitled *Preliminary Release of Unix Implementation*. It was unearthed from the Computer History Museum by Al Kossow, scanned, and digitally transcribed into assembly source files.

## Key Source Code Files

| Component / Subsystem | File Link | Description |
| :--- | :--- | :--- |
| **Trap Vector & Syscall Dispatch** | `u1.s` | Entry point `sysent`: saves registers `r0` through `r5`, saves arithmetic unit accumulator `ac` and multiplier quotient `mq`, parses the system call vector, and dispatches to handler routines. |
| **Pathname Resolution & Inodes** | `u2.s` | Implementation of `namei` (filename to inode lookup), `syslink` (creating hard links), `iget` (reading inode into core memory), and `isdir` (directory verification). |
| **Scheduler & Process Switcher** | `u3.s` | The process queue scheduler (`swap`, `tswap`): inspects priority run queues (`runq`), selects the highest priority ready process, saves execution state, and performs context switches. |
| **Clock & Resource Accounting** | `u4.s` | Interrupt routine `clock`: triggers 60 times a second from the KW11-L line clock, updates system time (`s.time`), and charges process execution time (`s.syst`). |
| **File Block Mapper** | `u5.s` | Routine `mget`: translates logical byte offsets into physical 512-byte disk blocks, handles direct blocks (`i.dskp`), and allocates indirect blocks for larger files via `alloc`. |
| **Character & Special File Routing** | `u6.s` | Routine `readi`: checks whether an inode represents a device special file (inodes 1–40) or a regular disk file, routing requests to `rtty` or `dskr`. |
| **TTY Canonical Line Discipline** | `u7.s` | Routine `canon`: parses teletype input lines, implementing `#` for backspace/erase and `@` for kill line, copying normalized characters to user buffers. |
| **Storage Drivers** | `u8.s` | Block storage drivers for the DECtape (`rtap`, `wtap`), RF11 fixed-head drum (`rdr`, `wdr`), and RK03/RK05 moving-head disk cartridge (`rrk0`, `wrk0`). |
| **Console & Serial Interrupts** | `u9.s` | Serial interrupt drivers (`trcv` receiver interrupt, `txmt` transmitter interrupt) for asynchronous terminal lines. |
| **Hardware Manifests & I/O Vectors** | `u0.s` | Memory-mapped device registers for the PDP-11/20 (KW11-L, TC-11 DECtape, RF-11 drum, and DC-11 lines). |
| **Kernel Data Structures & Inode Definition** | `ux.s` | Inode structure layout in memory: `i.flgs` (flags), `i.nlks` (link count), `i.uid` (user ID), `i.size` (file size in bytes), and `i.dskp` (allocated block pointers). |
| **Command Interpreter (Shell)** | `sh.s` | Ken Thompson's First Edition assembly Shell: processes user commands, forks child processes, sets up I/O redirection (`<`, `>`), supports background execution (`&`), and configures the `#` prompt for root. |
| **System Initialization** | `init.s` | The ancestor of PID 1: tests the PDP-11 console console switch register (`cmp csw, $73700`), spawns the single-user shell or forks multi-user logins across teletypes. |

## Recommended Exploration Path

To understand the core design of First Edition Unix:

1. **Start with the Inode and Hardware Memory Map:**
   Read `ux.s` to understand the layout of an inode (`i.flgs`, `i.nlks`, `i.uid`, `i.size`, `i.dskp`) and the system metrics block, followed by `u0.s` for the PDP-11/20 memory-mapped I/O registers.
2. **Trace the System Call Mechanism:**
   Read `u1.s`. Observe how the PDP-11 `sys` instruction (an alias for `trap`) pushes the processor status and PC, saves all general registers, and decodes the operand to find which syscall to invoke.
3. **Follow File Creation, Reading, and Inode Traversal:**
   Read `u2.s` to see the original implementation of `namei`. Then trace `u5.s` (`mget`) and `u6.s` (`readi`) to see how bytes are translated into 512-byte disk blocks.
4. **Study Multiprogramming & Scheduling:**
   Examine `u3.s` to understand how the primitive round-robin priority queues operated on hardware with no paging or memory protection unit.
5. **Explore Userland and the Original Shell:**
   Read `sh.s` to see how the command interpreter was originally structured before C existed, followed by `init.s`.
